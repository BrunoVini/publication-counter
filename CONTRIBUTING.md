# Contributing to PubCount

Thanks for helping. Small fixes, translations and ideas are all welcome.

## What this is

PubCount is an offline Svelte 5 + TypeScript PWA that inventories publications by weight: weigh a sample, weigh the pile, get the count. There is no server and no account; data stays on the device.

## Run it

Use the Node version in `.nvmrc` (`nvm use`), then:

```
npm ci
npm run dev
```

## Gates

Before opening a PR, all of these must pass (CI runs the same):

```
npm run lint && npm run check && npm test && npm run build
```

ESLint enforces `max-lines` of 200 per file, ignoring blank lines and comments. Split a file instead of raising the limit.

## Commits

Conventional commits in English: `type(scope): subject`, lowercase, imperative, no trailing period. Types in use: `feat`, `fix`, `refactor`, `test`, `style`, `chore`, `docs`. The scope is optional but usual (`ui`, `i18n`, `data`, `drive`, ...). Examples from the history:

```
feat(i18n): lazy-load locales and add 12 ui languages
fix(ui): keep conflict dialog open and announce drive status
chore(lint): enforce max-lines everywhere
```

Add a body when the reason is not obvious from the subject.

## Code and text

- Code, comments and identifiers are in English.
- UI text lives only in `src/i18n/*.json`, never in components.
- All locales have identical keys (a test checks this). Plural forms follow `Intl.PluralRules` for that language: use the suffixes it produces (`_one`, `_few`, `_many`, `_other`, ...) and provide `_other`.

## Translations

The UI is available in 15 languages. **The 12 newer ones (zh, hi, fr, ar, bn, ru, ur, id, de, ja, tr, mr) were machine-translated, and review by native speakers is very welcome.** Wrong, stiff or unnatural wording is a perfectly good reason to open a PR or an issue.

To fix a string, edit the key in `src/i18n/<lang>.json` and keep the placeholders (`{count}`, `{word}`, ...) as they are. Do not rename or reorder keys.

To add a language:

1. Create `src/i18n/<lang>.json` with every key of `src/i18n/en.json`.
2. Add the tag to the `LANGS` list in `src/domain/types.ts` (this defines the `Lang` type).
3. Add its Intl locale to the `locales` map in `src/i18n/index.svelte.ts` (and to `RTL` if it is right-to-left).
4. Add its name, written in itself, to `NATIVE_NAMES` in `src/i18n/names.ts` (this feeds the language select).
5. Add its default publication language code to `DEFAULT_PUB_LANGUAGE` in `src/domain/dataset.ts`.
6. Add it to the languages list in `scripts/update-languages.mjs` (check the URL path it needs) and run the script to generate `src/data/language-names/<lang>.json`.

## Languages data

`src/data/languages.json` and `src/data/language-names/*.json` are generated by `scripts/update-languages.mjs`, which a workflow runs monthly and turns into a PR. Do not edit them by hand; change the script instead.

## Privacy

PubCount has no server, no analytics and no tracking, and sends nothing anywhere. The only network feature is the optional backup to the user's own Google Drive. Do not add telemetry, third-party scripts or anything that moves data off the device.

The app shows no organisation names or logos.

## Issues and pull requests

Open an issue on GitHub to report a bug, suggest an idea or flag a bad translation; say what you did, what you expected and, for the UI, the language and device. For a PR, branch from `main`, keep it focused, describe what changed and why, and make sure the gates above pass.

`main` is protected: changes go through pull requests with CI green.
